# Weft

**WEFT** — World-building, Era, and Fantasy Timeline。

一个**没有边界、以 AI 协作为主要使用方式**的小说辅助写作工具。

WEFT 不只是把已有数据画成时间轴。它更重要的设计目标，是让作者不必学习和手写
结构化 YAML：安装 `weft-yaml` skill 并连接 WEFT MCP 后，可以直接对 Claude
Code、Codex 等 Agent 说：

> 在第三章加一个阿青和阿白在车站相遇的事件，时间是听证会结束两天后。

Agent 会理解故事格式，找到对应的实体、事件和时间锚点，修改故事文件，再调用
WEFT 的真实后端校验引用与时间计算。作者负责讲清创作意图，Agent 负责维护精确的
结构化数据。

桌面界面则用于浏览 Agent 和作者共同构建的时间轴、实体关系和叙事视角。

## AI 原生工作流

WEFT 为 Agent 提供两个互补层次：

- **`weft-yaml` skill**：告诉 Agent WEFT 的概念、文件结构、编辑原则和推荐工作流。
- **WEFT MCP server**：提供实时 schema、文件校验、故事检查和时间线解析；它与
  桌面应用使用同一套 Rust 领域模型。

典型流程是：

```text
作者用自然语言描述修改
          │
          ▼
Agent 根据 skill 编辑故事文件
          │
          ▼
Agent 调用 MCP 校验并解析时间线
          │
          ▼
作者在桌面端查看时间轴、关系和 Narrative
```

YAML 是适合版本控制和 Agent 编辑的底层交换格式，不是要求作者亲自操作的用户
界面。安装方式和 Agent 配置见 [AI 与 MCP](mcp.md)，完整字段见
[YAML 规范](weft-yaml.md)，字段背后的取舍见 [DAO 字段设计](dao.md)。

## 设计理念

WEFT 有两条同等重要的设计原则：**AI 友好**和**无边界**。

AI 友好解决的是“作者怎样操作数据”：作者表达创作意图，Agent 维护结构化故事，
MCP 用真实后端验证结果。

无边界解决的是“工具允许作者创造什么”：大多数写作工具默认故事是关于人的，
角色有一套固定档案，时间线使用公历，世界遵循现实规则。WEFT 不做这些假设。
它只提供足以建立故事结构的少数原语，而不替作者定义世界。

**Moai 可以是任何东西。** 人物、街区、王朝、一把刀、一场台风，甚至一个抽象
观念——任何在时间中存在或被时间观察的东西，都是 [Moai](moai.md)。

**Drift 可以是任何变化。** 一次会面、一场战争、一段迁徙、城市的扩张、季风的
到来，都可以成为 [Drift](drift.md)。WEFT 不预设“情节”只能发生在角色身上；
事件只是把 Moai、时间与描述关联起来。

**属性由作者定义。** WEFT 不内置职业、阵营、种族、地理类型、力量等级或魔法
体系。Moai 除了最小公共字段外，可以携带任意故事属性；material 还能读取这些
属性和时间锚点，计算作者需要的派生信息。Agent 根据当前故事的语义维护它们，
而不是被软件预设的表单限制。

**时间也由作者定义。** 格里高利历只是三个内置实现之一。通过
[Aqueduct](phase.md)，作者可以定义时间单位、进位规则、显示方式和时间轴坐标：
十天一旬、三旬一月、四月一年，或完全不同的纪年方法，都可以成为故事自身的
时间系统。

三条线交汇处就是故事：

```
实体 (Moai) ── 什么在时间中存在？
事件 (Drift) ── 发生了什么变化？
时间 (Phase/Aqueduct) ── 世界怎样度量时间？
```

Moai 和 Drift 是核心叙事原语，关系用于组织它们，Aqueduct 决定时间如何流动。
WEFT 提供脚手架，但不替作者决定世界里能有什么。这就是“无边界”。

**Narrative 有意比世界建模严格。** 世界可以无边界，但小说最终必须从某个视角被
讲述。Narrative 是为最后的小说叙事准备的：它从已有 Drift 中选择素材，并为这一
段叙事固定一个 observer。这个 observer 必须出现在所有被选事件中，防止大纲在
没有说明的情况下越过视角人物能够观察或经历的范围。

这种严格不是对世界观的限制，而是对“怎样讲述这个世界”的约束。固定视角是小说
写作的基本原则；如果需要另一个视角，应建立另一个 Narrative，明确完成叙事视角
的切换。

## 名字

这些名字不是随意选取的术语，它们共同描述了一条时间之河。

**道（Dao）。** Dao 取自中文“道”。它是故事中万物汇集、彼此关联并进入时间的
整体路径，也是 WEFT 加载一份故事后形成的完整领域对象。

**流（Drift）。** 子在川上曰：“逝者如斯夫，不舍昼夜。”时间像水一样不停
流逝，事件随时间经过世界中的万物。Drift 因此不是静态资料，而是被时间推动的
变化与经过。

**石（Moai）。** 时间之水流过石头，石头在水中形成可被观察的存在。人物、城市、
王朝和物件都像这样的石头，被不同事件经过。`stone` 虽然准确，却太普通；复活节
岛上的 Moai 石像沉默、稳定地伫立，更适合作为 WEFT 核心实体的名字。

**渠（Aqueduct）。** 水流需要渠道来规定方向。历法也在规定时间怎样流动：有哪些
单位、何时进位、怎样显示、如何映射到时间轴。Aqueduct 就是时间的引水渠；更换
渠可以改变世界度量时间的方式，但 Moai 与 Drift 的基本关系不变。

```
道 (Dao) ── 故事万物汇集和运行的整体路径
流 (Drift) ── 随时间之水发生的事件与变化
石 (Moai) ── 伫立水中、被事件经过的存在
渠 (Aqueduct) ── 规定时间之水如何流动的历法
```

## 架构

```text
React + Vite ──Tauri IPC──> Rust 领域内核 ──> Rhai 故事脚本
```

- Tauri/Rust 负责桌面窗口、系统集成、领域模型和 standalone 发行。
- React + TypeScript + Vite 负责界面，不需要 Node.js 服务器。
- Rust 负责 YAML 解析、交叉引用和时间计算；Rhai 负责自定义历法与 material。
- 应用不启动 HTTP API，也不携带 Python 运行时。

## 快速开始

```bash
# 启动 Tauri 桌面应用
cargo tauri dev -- examples/红楼梦.yml
```

连接 AI Agent 见 [AI 与 MCP](mcp.md)。
