# DAO 字段设计

`Dao` 是 WEFT 加载一个故事后得到的完整领域对象。它不是单纯的 YAML
反序列化结果：加载过程还会选择历法、运行 material、解析实体引用、计算时间、
建立 journal，并检查 Narrative 的固定视角。

Dao 取自中文“道”。这套领域名称共享同一个时间之河的隐喻。子在川上曰：
“逝者如斯夫，不舍昼夜。”事件是随时间流逝的 Drift；实体则像水流中稳定的
石头。`stone` 太普通，因此实体以复活节岛上伫立的石像 Moai 命名。Aqueduct
是引水渠，它规定时间之水的单位、进位、显示和方向。Dao 则把石、流与渠汇集成
一份可以被理解和计算的完整故事。

这一组字段围绕三条设计原则：

1. **AI 友好**：结构稳定、引用明确，Agent 可以可靠地局部编辑并用 MCP 校验。
2. **世界无边界**：只规定少数叙事原语，不预设作者的世界里有哪些类型和属性。
3. **叙事有纪律**：世界建模保持开放，进入 Narrative 后则明确固定观察视角。

## 故事文件与 Dao

故事文件顶层通常包含：

```yaml
aqueduct: {} # 可选的历法插件注册
material: {} # 可选的派生属性插件注册
story: {}
moai: {}
moai_link: {}
drift: {}
narrative: {}
```

其中 `aqueduct` 和 `material` 是加载配置：它们会在构造 `Dao` 前注册插件，
不作为 `Dao` 的输出字段。最终的 `Dao` 包含 `story`、`moai`、`moai_link`、
`drift` 和 `narrative`。

## `story`：作品级约定

`story` 描述整份故事共同遵循的最小元信息。

| 字段 | 设计意图 |
|------|----------|
| `title` | 给作品一个稳定、可展示的身份；因此必须是字符串 |
| `description` | 记录作品级简介或创作前提，不强迫作者套用固定分类 |
| `date_mode` | 为整份故事选择同一套 Aqueduct，保证所有实体和事件可以比较与计算；默认为 `gregorian` |

`story` 没有内置题材、时代、受众或类型等字段。这些不是时间和引用计算所必需的
公共约束，不应由 WEFT 替作者决定。

## `moai`：世界中存在的东西

`moai` 是“名称 → Moai”的映射。用名称作为键，是为了让 Agent 和作者都能以
自然语言引用实体，也让关系、事件和视角检查具有明确目标。

| 输入字段 | 设计意图 |
|----------|----------|
| 映射键 / `name` | 实体的稳定身份；加载后成为 Moai 的 `name` |
| `description` | 用自然语言说明它是什么，默认为空字符串 |
| `base_time` | 可选的时间锚点，可以是出生、建立、出现或任何由作者定义的起点 |
| `materials` | 指定需要运行的派生属性函数 |
| 任意其他字段 | 作为作者自己的世界属性保存在 `extra_props` |

Moai 不等于“人物”。城市、王朝、武器、风暴或观念都可以成为 Moai。WEFT
没有职业、阵营、物种、地点类型等固定字段，因为这些概念属于具体作品。

加载后还会生成以下字段：

| 派生字段 | 设计意图 |
|----------|----------|
| `extra_props` | 汇集作者自定义属性与 material 计算结果 |
| `base_time_display` | 使用所选 Aqueduct 展示解析后的锚点 |
| `journal` | 记录该 Moai 参与的 Drift 相对于 `base_time` 的开始、结束偏移 |
| `aqueduct` | 内部计算依赖，不序列化给前端或 MCP |

`journal` 不应手写。它让同一个事件可以从不同 Moai 的时间尺度被理解，例如人物
当时的年龄、城市建立后的年份，或王朝开始后的阶段。

## `moai_link`：显式关系

`moai_link` 是“关系分组 → 关系列表”的映射。分组用于界面组织，不规定关系的
语义类型。

| 字段 | 设计意图 |
|------|----------|
| 分组名 | 将人物关系、地理关系等边组织在一起，由作者自由命名 |
| `moais` | 恰好引用两个已有 Moai，防止关系指向不存在的实体 |
| `relations` | 用自然语言描述关系，不限制为预设枚举 |
| `bidirectional` | 表达关系是否双向，默认为 `true` |

关系被独立于 Moai 保存，是为了避免把网络结构嵌套进某个实体，也便于前端生成图。
`relations` 使用自由文本，是“无边界”原则的体现：朋友、统治、位于、象征或
作者创造的关系都不需要修改模型。

## `drift`：时间中发生的变化

`drift` 是“事件分组 → 事件映射”。加载后每个分组变为 Drift 列表。

| 输入字段 | 设计意图 |
|----------|----------|
| 分组名 | 组织同一章节、阶段或事件链；不是固定的“章”类型 |
| 事件标题 | 让作者和 Agent 可以自然引用事件，并参与生成稳定 ID |
| `start_time` | 每个事件必须有时间位置，才能进入统一时间线 |
| `end_time` | 可选；区分时间点和持续事件，且不得早于开始时间 |
| `description` | 保存事件内容，不规定情节类型 |
| `moais` | 明确哪些实体参与或出现在事件中，并校验引用存在 |

事件标题目前限制为 20 个字符，是展示层面的紧凑约束，不是世界观分类。
Drift 可以是人物行动，也可以是城市扩张、王朝更替或气候变化。

加载后生成：

| 派生字段 | 设计意图 |
|----------|----------|
| `id` | 由 `分组/标题` 组成，供 Narrative 精确引用 |
| `flat_start` / `flat_end` | 展开相对时间引用后的时间分量 |
| `start_tick` / `end_tick` | Aqueduct 提供的统一时间轴坐标 |
| `start_time_display` / `end_time_display` | 依照故事历法生成的展示文本 |
| `aqueduct` | 内部计算依赖，不写入故事文件 |

这些派生字段也不应由作者或 Agent 手写。

## `narrative`：把世界材料组织成小说叙事

`narrative` 是“叙事名称 → Narrative”的映射。它不是另一类世界实体，而是从
已有 Drift 中选择素材，为最后写成小说建立固定视角的大纲。

| 输入字段 | 设计意图 |
|----------|----------|
| Narrative 名称 | 标识一段大纲、章节线或 POV 线 |
| `subject` | 按写入顺序选择 Drift 分组或精确的 `分组/事件` ID |
| `observer` | 固定这一段叙事的观察者，必须引用已有 Moai |

加载后的 `drifts` 是 `subject` 展开得到的事件副本。分组按照故事文件里的事件
顺序展开，当前不会按绝对时间重新排序。

Narrative 刻意比其他字段严格：`observer` 必须出现在每一个被选 Drift 的
`moais` 中。世界本身可以无边界，但小说必须明确“谁能够看见、经历或讲述这些
内容”。如果要切换视角，应建立新的 Narrative，而不是在同一个 Narrative 中
隐式越界。

## `aqueduct`：时间规则由世界决定

顶层 `aqueduct` 把历法名称注册到 Rhai 插件：

```yaml
aqueduct:
  gethen:
    runtime: rhai
    kind: calendar
    api: 1
    source: ./calendars/gethen.rhai
story:
  title: 黑暗的左手
  date_mode: gethen
```

Aqueduct 通过 Brick 定义时间单位和进位规则，还可以定义格式化方式与时间轴坐标。
它存在的设计原因是：时间不应天然等于现实世界公历。幻想历、循环纪年或作品特有
的时间单位，都应由世界自身决定。详见[时间引擎](phase.md)。

## `material`：让属性可扩展、可计算

顶层 `material` 注册“名称 → Rhai 脚本文件”。Moai 的 `materials` 引用这些
名称，加载时把函数返回值写入 `extra_props`。

Material 把“作者自由定义属性”进一步扩展为“作者自由定义计算规则”。例如可以
根据生日计算星座，根据阵营和声望计算称号，或根据城市人口和资源计算等级，而
不需要向 WEFT 核心模型增加字段。

Aqueduct 和 material 都在受限 Rhai 运行时中执行，不默认开放文件系统和网络。

## 为什么有些字段自由、有些字段严格

WEFT 只严格约束跨对象计算所必需的部分：

- 引用必须指向已有对象；
- 时间必须能被所选 Aqueduct 解析；
- 事件结束不得早于开始；
- Narrative 必须保持固定 observer。

世界的类型、属性、关系语义和事件内容则留给作者。这个边界使 Agent 能可靠地
编辑和验证故事，又不会让验证模型反过来限制创作。
